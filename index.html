01 // PROBLEM STATEMENT & THREAT LANDSCAPE

Why Shared Cloud Sandboxes Fail Audit Scrutiny

Core issue: Today's safety evidence is "trust us" instead of cryptographic proof.

FAILURE MODE 01 PEEKING

Blue Sees Red's Raw Attack Payloads

When Red and Blue share a container network or filesystem, Blue can inspect incoming raw attack headers or payload staging files. The defense adapts to attacks it should never have seen—making guardrail efficacy look artificially stronger than it really is.

TriSeal Fix: Separate networks + bilateral commit-reveal + normalized Airlock traffic.
FAILURE MODE 02 SIDE CHANNELS

Red Infers Blue's Logic via Timing & Size

A fast 12ms response reveals an immediate regex/classifier block, while a 420ms response reveals LLM generation. Attackers use timing differentials, packet sizes, and DNS/ICMP covert channels to reverse-engineer Blue's proprietary filter logic.

TriSeal Fix: 4096B deterministic padding + 250ms fixed-cadence Airlock + Leak Hunter CI.
FAILURE MODE 03 CONTAMINATION

Model & KV-Cache Cross-Contamination

Shared vLLM/Ollama prefix caches (docs.vllm.ai), leftover session context, and noisy-neighbor CPU/IO contention mean evaluation scores reflect environmental artifacts rather than true model safety.

TriSeal Fix: Model Gateway session wipe + salted KV-cache + Twin-Run clean baseline.
FAILURE MODE 04 NO PROVENANCE

Findings Cannot Be Proven in Disputes

Standard container logs can be altered or cherry-picked after a test run. Neither AI labs, red-team vendors, nor regulators (NIST AI RMF / EU AI Act) can independently verify that isolation held.

TriSeal Fix: SHA-256 hash chain + ed25519 Merkle checkpoints + Portable Certificate.
